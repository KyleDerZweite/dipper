# Domain docs

Dipper uses a single-context layout. Domain vocabulary belongs in `GLOSSARY.md` at the repository root. Architecture decisions belong in `docs/adr/`.

Before exploring the project, read the glossary and ADRs relevant to the work. If these files do not exist, proceed without creating placeholders. Use `domain-modeling` to record terms and decisions when they are resolved.

Use the glossary's terms in issues, code, tests, and proposals. If a concept is missing, reconsider invented vocabulary or record the gap for domain modeling.

If a proposal contradicts an ADR, identify the decision and explain why it should be reconsidered. Preserve accepted decisions until a replacement is agreed.
